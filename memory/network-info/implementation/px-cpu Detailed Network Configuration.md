# px-cpu Detailed Network Configuration

## Interface Mapping (Discovered After Boot)

First, we need to identify the actual interface names after Proxmox installation:

```bash
# After boot, run:
ip link show
# Map physical ports to Linux interface names
# Likely pattern based on similar hardware:
# - eth0/eth1 or enpXs0/enpXs1 for 2.5Gb ports
# - enpXs0f0/enpXs0f1 for SFP+ ports
```

## Critical Configuration Notes

### 1. TSO (TCP Segmentation Offload) Disabled

Both px-net and px-nas disable TSO on bridges. This is critical for OPNsense compatibility:

```bash
pre-up ethtool -K enp3s0f0 tso off
post-up ethtool -K vmbr0 tso off
```

### 2. Bridge Numbering Must Match

For OPNsense CARP to work:

- vmbr0: VLAN trunk (vtnet0 in OPNsense)
- vmbr1: WAN (vtnet1 in OPNsense)
- vmbr2: MGMT/SYNC (vtnet2 in OPNsense)

### 3. VLAN Configuration

All VLAN-aware bridges need:

```bash
bridge-vlan-aware yes
bridge-vids 2-4094
```

### 4. Bond Configuration

Even with single interface, using bond0 provides:

- Consistency with other nodes
- Easy LACP addition later
- Standard configuration

## Post-Installation Verification

```bash
# 1. Verify bridges are created
brctl show

# 2. Check VLAN configuration
bridge vlan show

# 3. Verify management connectivity
ping 10.10.101.1
ping 10.10.101.12  # px-net
ping 10.10.101.13  # px-nas

# 4. Check interface status
ip link show
ethtool enp3s0f0  # Verify 10Gb link

# 5. Verify TSO is disabled
ethtool -k vmbr0 | grep segmentation
ethtool -k enp3s0f0 | grep segmentation
```

## OPNsense VM Network Configuration

When creating OPNsense VM on px-cpu:

```bash
# Network devices MUST be in this order:
net0: virtio,bridge=vmbr0    # LAN/VLAN trunk
net1: virtio,bridge=vmbr1    # WAN
net2: virtio,bridge=vmbr2    # SYNC

# This creates:
# vtnet0 -> vmbr0 (VLAN trunk)
# vtnet1 -> vmbr1 (WAN)
# vtnet2 -> vmbr2 (SYNC)
```

## Troubleshooting Interface Naming

If interfaces don't match expected names:

```bash
# 1. Use biosdevname to understand naming
biosdevname -i eth0

# 2. Check udev rules
cat /etc/udev/rules.d/70-persistent-net.rules

# 3. Use lshw to map interfaces
lshw -class network -businfo

# 4. Check PCI bus assignment
lspci | grep -i ethernet
```

## Interface Naming Contingency

If we can't get matching names, create udev rules:

```bash
# /etc/udev/rules.d/10-network.rules
# Map by MAC address to consistent names
SUBSYSTEM=="net", ACTION=="add", ATTR{address}=="xx:xx:xx:xx:xx:xx", NAME="enp1s0"
```
